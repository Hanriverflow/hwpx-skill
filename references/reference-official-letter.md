# 실제 참고 양식에 맞춘 공문 재작성

사용자가 실제 공문 PDF·이미지·HWPX를 제공하며 양식을 따르라고 할 때 읽는다. 기존 결과가 “공문 같지 않다”는 피드백을 받았다면 제목 크기만 바꾸기 전에 두문·본문·결문 구성이 참고 문서와 어떻게 다른지 확인한다. 참고 문서가 없는 일반 공문은 기존 `official-letter` 경로를 유지한다.

## 1. 양식 출처와 내용 출처를 분리한다

- “내용은 다르지만 양식을 따르라”는 요청에서는 참고 파일은 서식 근거이고, 원고는 사실 근거다. 참고 문서의 날짜·수신자·정책·문서번호를 새 문서에 가져오지 않는다.
- 타 기관의 로고·표어·직인·서명·결재자를 모양 때문에 복제하지 않는다. 실제 발신자에 사용하도록 제공된 자산만 사용한다. 연락 담당자를 기안자·결재권자로 바꾸지 않는다.
- 기업 공문에 정부 시행문의 시각 형식을 적용하는 것은 정부기관의 신분·결재 절차까지 적용하는 것이 아니다. 확인된 시행·연락 정보로 결문을 구성하고, 미제공 주소·접수번호·공개구분 등을 채우기 위해 사실을 만들지 않는다.
- `수신`, `참조`, `(경유)`는 뜻이 다르다. 원고의 참조 담당자가 생성기에서 지원되지 않는다고 `(경유)`로 바꾸거나 누락하지 않는다. 발송에 필요한 미확정 정보는 초안 상태와 기입 항목으로 남긴다.

## 2. 텍스트 추출과 페이지 관찰을 함께 한다

환경에서 지정한 문서 읽기 도구를 우선 사용하되, 텍스트 추출 결과만으로 양식 분석을 끝내지 않는다. 관련 페이지를 이미지로 열어 실제 배치를 확인한다.

- HWP/HWPX: 원본 보존·변환 후 `doc_spec.py analyze` 또는 기존 파일 분석 경로를 검토한다.
- PDF: `doc_spec.py analyze`는 HWPX 전용이다. PDF를 직접 넘기지 않는다. 페이지 렌더와 사용 가능한 PDF 분석기로 글꼴·글자 크기·좌표·선을 확인한다.
- 스캔·이미지: OCR은 내용 확인에만 사용한다. 글꼴과 좌표는 관찰·추정임을 구분하며 정확한 수치라고 기록하지 않는다.

분석 결과는 작업 폴더에 간단한 배치 메모로 남긴다. 이는 작업별 설계 자료이지 `one_shot`에 임의 키를 추가하는 새 입력 스키마가 아니다.

| 영역 | 확인할 항목 |
|---|---|
| 용지·본문 폭 | 용지 크기, 좌우 기준선, 위아래 여백 |
| 두문 | 기관명 위치·글꼴·크기, 수신/참조 라벨과 값의 시작점, 제목 굵기·줄바꿈, 제목 아래 선 |
| 본문 | 글꼴·크기, 실제 줄 간격, 항목 사이 간격, 둘째 줄 이후 정렬 |
| 붙임 | 본문과의 간격, 번호·내용 정렬, 줄바꿈, 수량과 `끝.` 위치 |
| 결문 | 발신명의·날인 공간, 구분선, 결재·시행·연락처의 유무와 상대 위치 |

서로 다른 본문 길이에 동일한 좌표를 강제하지 않는다. 각 영역의 위계·정렬·상대 간격을 재현하되 내용에 맞춰 높이를 계산한다. 참고에 없는 카드·색상 배너·큰 별도 제목·쪽번호를 습관적으로 추가하지 않는다.

PDF의 글꼴 이름은 설치된 한글 글꼴 이름과 다를 수 있다. 실제 사용 가능 여부를 확인하고 대체 글꼴을 기록한 뒤 줄바꿈을 다시 검토한다. Windows에서 `*.ttf`만 검색하면 `*.ttc`의 돋움·굴림 같은 글꼴을 놓칠 수 있다.

12pt 글자에 기준선 간격 19pt라면 약 158%라는 계산은 출발점일 뿐이다. 12pt·158%·20mm·회색 굵은 선 같은 특정 참고 문서의 값은 모든 공문의 규정으로 승격하지 않는다. 내장 글꼴·줄간격·들여쓰기 기본값과 참고의 차이를 의식적으로 선택한다. 명시적인 서식 재현과 표준화 요구가 함께 충돌하면 그 차이를 알리고 우선순위를 확인한다.

## 3. 본문과 상세 붙임의 역할을 정한다

참고가 짧은 시행문이고 원고가 긴 거래·계약 설명이라면, 요청 취지·핵심 금액/기한/대상·구체적 처리 요청·중요한 제외 조건은 본문에 남기고 상세 내역은 붙임으로 분리하는 구성을 검토한다. 이 편집 방향을 사용자에게 알린다. 모든 공문을 1쪽 또는 본문+붙임 2쪽으로 고정하지 않으며, 표가 있는 참고 양식이나 사용자의 본문 표 유지 요청을 우선한다.

원문 보존 또는 축약 금지 요청에서는 임의 요약하지 않는다. 분리하더라도 필수 사실이 사라지지 않도록 원고→본문/붙임의 대응을 남긴다. 특히 금액·계좌·예금주·거래시각·계약 조항·담당자·예외/비취소 조건은 개별 대조한다. 새로 작성한 요약문과 산출물끼리만 비교하면 요약 단계의 누락을 찾을 수 없다.

붙임을 추가하면 본문의 인용, 붙임 목록 번호·제목·수량, 실제 붙임 제목을 함께 갱신한다. 목록에 적힌 증빙과 HWPX에 실제 포함한 붙임을 구별한다. 미제공 계좌 사본·확인증 등이 첨부 완료된 것처럼 안내하지 않는다.

## 4. 편집 가능한 구조로 조립한다

기존 생성기·템플릿을 재사용한다. 다만 스키마가 지원하지 않는 참조란·상세 붙임 표·참고별 글꼴/배치가 필요하면 지원 여부를 확인하고 고급 조립 경로를 사용한다. 미지원 키를 추측해 넣거나 표를 문자열로 평탄화하지 않는다. 원샷 밖에서 생성했다면 메인 `SKILL.md`의 최종 검사 경로를 끝까지 따른다.

- 문단·라벨·선·표를 네이티브 HWPX 요소로 만든다. 참고 페이지를 배경 이미지로 붙이는 것으로 편집 가능한 재현을 대신하지 않는다.
- 줄바꿈·들여쓰기·셀 크기는 렌더에서 확인한다. HWPX의 왼쪽 여백과 음수 내어쓰기를 함께 적용하면 예상보다 깊은 들여쓰기가 생길 수 있다. 실제 첫 줄과 계속 줄의 시작점을 비교한다.
- 선은 문단 테두리 등으로 구현하고, 반복 문자로 길이를 맞추지 않는다. 발신명의와 하단 시행정보가 서로 떨어져 다음 쪽으로 밀리지 않도록 함께 검토한다.
- 파일·스크립트의 경로와 텍스트 I/O는 UTF-8로 처리한다. Python 관리 방법은 작업 환경의 지침을 따른다. Windows에서는 `PYTHONUTF8=1` 또는 필요한 표준출력 UTF-8 설정을 실행 전에 적용한다.

## 5. 원본 양식과 실제 한컴 출력을 대조한다

정적 검증 → 독립 한컴 열림 → PDF/페이지 PNG 렌더 → 모든 페이지 육안 검토를 구별해 기록한다. 네 단계가 성공해도 참고 양식과의 대조가 없으면 “양식을 반영했다”는 근거로 충분하지 않다.

확인할 차이:

- 기관명·수신·제목·본문 시작점, 본문 폭과 정렬, 문단 간 여백
- 붙임과 발신명의 사이 공간, 날인 자리, 결문 구분선과 연락처 영역
- 표 잘림·행 분할·과도한 축소, 마지막 쪽에 짧은 문단만 남는 현상
- 글꼴 대체와 긴 제목/발신명의로 생긴 재줄바꿈, 계좌·금액의 가독성

문제는 먼저 문단 간격·표 열폭·명시적 쪽 나눔·본문/붙임 구성을 조정한다. 공간을 맞추려고 필수 사실을 삭제하지 않는다. 레이아웃 휴리스틱이 붙임 제목·발신명의·의도적인 문단 정렬을 경고하면 해당 위치를 확인해 처리 이유를 기록하며 일괄 무시하지 않는다.

최종 HWPX의 해시와 검토한 렌더 리포트의 원본 해시가 같은지 확인한다. 검증기나 후처리가 파일을 바꿨으면 다시 렌더한다. 원본 및 이전 버전은 보존하고 새 버전으로 전달한다. 저장 뒤 경로 출력에서 인코딩 오류가 났다면 재생성부터 하지 말고 대상 파일·해시·리포트의 게시 상태를 먼저 확인한다.

결과에는 적용한 양식, 실제 구성과 검사 상태, 발송 전 기입·별첨할 항목을 간결하게 알린다. 이 절차의 작업별 원고·실명·계좌·직인·고객 파일은 재사용 스킬의 예제나 테스트에 복사하지 않는다.
